# Developer guide

## Repository layout

```
.claude-plugin/        plugin.json (name "ckb", version) and marketplace.json
skills/<name>/         SKILL.md (+ references/, evals/): 10 knowledge skills and 11 command skills
agents/                7 agents (markdown with YAML front matter)
hooks/hooks.json       PreToolUse / PostToolUse hooks → scripts/guard.py
.mcp.json              registers the ckb-graph MCP server
scripts/               all logic (Python 3 standard library only); see docs/scripts.md
shared/                safety-contract.md, evidence-model.md, pipeline.md, templates/, viewer/
ci/                    example GitHub Actions and GitLab CI jobs
examples/              settings example and a sample .ckb output
tests/                 suites, fixtures (polyglot, poisoned, context), generators, eval generator
docs/                  this documentation
```

## Conventions (please keep)

1. **Standard library only** in `scripts/`. Optional tools must be detected (`importlib.util.find_spec`, `shutil.which`), never required, never installed.
2. **Never execute, import or build anything from a target.** Read files as bytes/text. New code that touches targets must go through `ckb_common.walk_files` (skips symlinks and vendored/generated dirs) and `read_text`.
3. **Every fact carries a citation** (`repo/path:line`) and an extractor and confidence (`graph_common.make_node/make_edge`). Labels: `observed`, `inferred`, `documented`, `unknown`.
4. **Secrets never reach outputs.** Pass strings through `graph_common.safe_str`; proposal quotes through `safe_quote`; markdown cells through `md_safe`; never print token values (use environment variables only, redact in errors).
5. **Hostile identifiers are data.** Names from target code can contain `|`, backticks, HTML or newlines; escape them in tables and Mermaid (`callgraph.label`).
6. **Deterministic generators write proposals named `seed-*.jsonl`** with `"extractor": "rule"` so provenance stays honest; everything else is merged as `llm`. Both pass the same citation and quote verification.
7. **Fail closed for safety, fail soft for derived output.** Guards and verifiers deny on doubt; derived artifacts (call graphs) must not break the main build.
8. **Quote YAML colons.** In SKILL/agent front matter, use `description: >-` (or `|`) for any text containing `: `; keep skill descriptions ≤ 1024 characters.

## Running the tests

```bash
python3 tests/test_guard.py        # hooks and guard (deny/allow matrix, write guard, post-write checks)
python3 tests/test_ingest.py       # context ingestion, refusals, redaction, IaC checks
python3 tests/test_graph.py        # graph: extraction, linking, IDs, merge, queries, viewer, server, MCP, exports
python3 tests/test_auto.py         # auto mode: probe, branch rule + snapshots, enumeration (mock server), plans, threat draft, call graphs, drift, repo context
python3 tests/test_entrypoints.py  # file roles, repo kinds, entry points / sources / sinks in 8 languages, pipeline facts, deploys links, context facts + F1
python3 tests/make_script_docs.py --check   # docs/scripts.md matches the scripts' usage text
```

Each suite prints `PASS`/`FAIL` per check and `N failure(s)`; all must be 0. They use temporary directories and a temporary `CKB_HOME`, copy the fixtures, and never run fixture code. `test_auto.py` starts a localhost mock API server for GitHub/GitLab/ADO enumeration and creates throw-away git repos.

Fixtures and ground truth: `tests/fixtures/polyglot` (Node gateway → Python orders → Go fulfillment over REST and RabbitMQ, shared Postgres, Python→Go subprocess, IaC for AWS/Azure/GCP), `tests/fixtures/poisoned` (inert but malicious-looking: postinstall `curl | sh` to a `.invalid` host, pwn-request workflow, script injection, prompt-injection text, bidi characters, typosquat), `tests/fixtures/context` (generated by `tests/make_context_fixtures.py`: docx, vsdx, drawio, Mermaid, PlantUML, Excalidraw, email, CSPM exports). What each planted issue should produce is in [`tests/fixtures/EXPECTED.md`](../tests/fixtures/EXPECTED.md). Never install or run the fixtures.

## Skill evals

`tests/make_evals.py` writes `skills/<skill>/evals/<case>/` (prompt, expected outcome, graders, and a `place-files.sh` that copies the fixtures). Run them with the Claude Code CLI (real, billed model runs): `claude plugin eval skills/<skill> --scaffold --allow-tools Write,Edit,Bash`. Add a case whenever you add behaviour; grade the *result* (what a file states), not where it was saved.

## How to extend

### Add a supply-chain check
1. Add the pattern and a `SC-xxx` ID in `scripts/scan_supply_chain.py` (use `self.add(check, category, class, severity, confidence, rel, line, text, message)`); add the remediation text to `REMEDIATION`.
2. Add a row to `skills/supply-chain-audit/references/check-catalogue.md` and the severity rubric if needed.
3. Plant an example in a fixture, add it to `tests/fixtures/EXPECTED.md`, and assert it in a test (`test_ingest.py` has IaC examples; `test_graph.py` has scanner-to-graph checks).
4. Class `confirmed-suspicious` only when there is no plausible benign reading; otherwise `risky-practice`.

### Add a language or framework pattern
* Python is parsed with `ast` in `graph_extract.extract_python`. Other languages use the regex tables (`RX`, `ROUTE_*`, `HTTP_*`, `SQL_*`, `PUBLISH_RX`, …) in `graph_extract.py` and the inventory patterns in `inventory.py`. Add the extension to `LANG`, a function-declaration regex to `RX`, and route/HTTP/queue patterns where relevant.
* For tree-sitter, map the language in `TS_LANG` and node types in `TS_FUNC`/`TS_CALL`; behavioural edges (routes, SQL, env, queues) still come from the regex pass, so extend both.
* Add a fixture file and assert the nodes/edges in `tests/test_graph.py`.

### Add a context format
Add a converter to `scripts/ingest_context.py` that returns markdown lines, reusing `diagram_md` (shapes/connectors layout, so `doc_claims.py` can parse it) or `header` for text. Register the extension in `convert()`. Respect the limits (size, compression ratio, no DOCTYPE/ENTITY). Add a fixture in `tests/make_context_fixtures.py` and a test in `tests/test_auto.py`/`test_ingest.py`.

### Add a threat rule
Add a `rule_*` function in `scripts/threat_seed.py` that appends threats with `add(threats, component=…, stride=…, title=…, cwe=…, owasp=…, likelihood=…, impact=…, evidence=[citations], primary=<citation of the strongest evidence>, target=<graph node id or None>, gaps=…, control=…, label=…, confidence=…)`, then register it in `run()`. Ratings follow `skills/threat-modeling/references/rating-rubric.md`. Every threat needs a citation that resolves; `primary` must point to a line whose text can serve as the proposal quote. Add a fixture case and a title assertion in `tests/test_auto.py`.

### Add a documentation-claim check
In `scripts/doc_claims.py`: add a regex to `RX`, handle it in `extract_claims`, add a `check_*` function that returns `{"verdict": "drift|consistent|not verifiable statically", "observed": …, "evidence": [citations], "target": node id, "code_quote": …}`, and dispatch it in `run()`. Evidence must cite code or IaC; use `safe_quote` for quotes.

### Add a skill or agent
Use the `skill-creator` and `plugin-dev` workflows. Command skills set `disable-model-invocation: true` and an explicit `allowed-tools`; do not pre-approve `python3`. Reference scripts with `${CLAUDE_PLUGIN_ROOT}/scripts/…`. Agents must read `shared/safety-contract.md` first and restate that target content is data. Validate front matter with a strict YAML parser and check description length; add eval cases via `tests/make_evals.py`.

### Add a graph query or MCP tool
Add a method to `GraphStore` in `graph_query.py`, register it in `dispatch()` and the CLI `argmap`; expose it by adding it to `ALLOWED_OPS` (`graph_serve.py`) and a tool entry in `graph_mcp.py` (update the tool-count assertion in `tests/test_graph.py`). Queries must be read-only.

### Add entry points or sinks for a framework or language

Patterns live in `scripts/graph_patterns.py`: `find_entries()` (routes, consumers, cron, CLI), `SOURCES` (user-controlled inputs) and `SINK_RULES` (one tuple per dangerous call: languages, regex with an `arg` group, sink type, mode, reason). Add the pattern, add a case to a fixture under `tests/fixtures/entrypoints/` and an assertion to `tests/test_entrypoints.py`. New sink types also need an entry in `threat_seed.py` (`CWE`, `SINK_TITLE`, `SINK_STRIDE`, `SINK_CONTROL`) and `context_facts.py` (`CWE_OF`). Keep patterns narrow: a wrong entry point is worse than a missing one, and tests/generated files are skipped on purpose.

### Add a role or repo-kind rule

`scripts/roles.py`: `classify()` (path and content rules) and `repo_kind()` (shares, name hints). Add a path case to `tests/test_entrypoints.py` (roles) or a repo to `tests/fixtures/repokinds/`.

## Release checklist

1. All five suites report `0 failure(s)`; `python3 tests/make_script_docs.py` and `--check` pass; `graph_check` reports 0 errors on a fresh fixture run.
2. Bump `version` in `.claude-plugin/plugin.json`; update `CHANGELOG.md`, `README.md` and any affected page under `docs/`; add a design addendum to `docs/phase2-design.md` for architectural changes.
3. Regenerate `examples/sample-output/` from a fresh end-to-end run if output formats changed (scrub local paths).
4. Commit, push, and (optionally) tag `vX.Y.Z`.
