# Language support

Every language below passes the same eleven-row conformance matrix in `tests/test_langs.py`: one realistic scenario per language (entry point, controller, service reached through a typed receiver, repository, library call, string-built SQL sink, an override, a test file and a generated file). This page is generated by `tests/make_language_docs.py` and checked against the test, so it cannot drift.

## What "covered" means

| # | Capability | Result required |
| --- | --- | --- |
| 1 | declarations | functions, methods and classes with qualified names and spans; strings and comments never produce calls |
| 2 | imports | in-repo imports resolve to files (`use`, `import`, `require`, `mod`, PSR-4, tsconfig paths, `go.mod`); externals become `package` nodes |
| 3 | calls | function, method, static, constructor, chained and callback calls resolved with a confidence; the rest are counted, never dropped silently |
| 4 | objects and classes | typed receivers (constructor, annotation, injected field), class hierarchy, `overrides`, `implements`, `uses_type`, class-level call graph |
| 5 | libraries | `calls_lib` edges from code to external packages, with the API names |
| 6 | entry points | each framework in the table below bound to its handler |
| 7 | sources | user-controlled inputs for those frameworks |
| 8 | sinks | SQL, command, SSRF, code, deserialization, template, XSS, path, redirect, NoSQL, LDAP, XPath, XXE (and memory, format, TLS, unsafe code where they apply) with safe/unsafe verdicts |
| 9 | auth evidence | the framework's route-, class- and middleware-level markers recognised |
| 10 | roles | test and generated files by language-specific rules |
| 11 | coverage | resolution accounting exists and the scenario's declared path resolved |

## Matrix

| Language | Parser | Frameworks and entry points | Known gaps |
| --- | --- | --- | --- |
| **python** | `ast` (stdlib) | FastAPI (routers with `prefix`), Flask (+ blueprints, `add_url_rule`), Django (`path`/`re_path`, DRF `router.register`), aiohttp, Tornado, Starlette, Sanic, gRPC servicers, AWS Lambda handlers, Celery, click/typer/argparse | `include_router(prefix=)` and Django `include()` prefixes across files are not joined; DRF viewset `@action` routes are not expanded |
| **javascript** | regex spec | Express/Koa/Fastify/Hono-style `x.verb('/path')`, `app.route().get()`, router mounts in the same file, Hapi, tRPC, cron/commander/BullMQ, React JSX component references, Angular `HttpClient` calls | router mounts across files, Fastify `register({prefix})`, Next.js server actions |
| **typescript** | regex spec | all of JavaScript plus NestJS (controllers, guards, constructor DI typed receivers, `@MessagePattern`, `@Cron`), Next.js `pages/api` and `app/**/route.ts`, tsconfig `paths` import resolution | Angular DI beyond constructor parameters; decorators that generate routes dynamically |
| **go** | regex spec | net/http (incl. 1.22 `"GET /x"` patterns), chi, gin/echo/fiber verb methods, gorilla `.Methods`, gRPC `Register*Server`, cobra, cron; receivers, embedded structs, `go.mod` imports | gRPC method handlers are not bound to the service entry; middleware groups are not followed |
| **java** | regex spec | Spring (`*Mapping`, class prefix), JAX-RS, Micronaut-style `@Get/@Post`, Servlets (`doGet/doPost`), Vert.x routers, Kafka/Rabbit/SQS/JMS listeners, `@Scheduled`; JDBC/JPA sinks | Struts, Spring functional routes, Quarkus-specific annotations |
| **kotlin** | regex spec | Spring-style controllers, Ktor routing (handler = enclosing function), extension functions as methods, primary-constructor DI typed receivers | Ktor nested `route("/x") { }` prefixes |
| **scala** | regex spec | Akka HTTP (`path("x") { post { } }`), http4s (`case POST -> Root / "x"`), Scalatra-style, traits and `extends ... with` | Play `conf/routes` is not parsed |
| **csharp** | regex spec | ASP.NET MVC attributes (`[Route]`, `[HttpGet]`, `[Authorize]`), minimal APIs, Azure Functions (HTTP/timer/queue triggers), interface-typed DI resolved to implementations | SignalR hubs, Blazor components |
| **ruby** | regex spec | Rails (`routes.rb` with `resources`, `namespace`; controllers; `before_action`), Sinatra/Grape (`get '/x' do`), Sidekiq workers, `X.new` constructors, `require_relative` | Hanami, Rails concerns and mixin dispatch |
| **php** | regex spec | Laravel (`Route::`, groups, `resource`, middleware), Symfony routes, Slim, WordPress hooks and REST routes, PSR-4 class resolution via `composer.json`, constructor-promotion DI | CodeIgniter/Yii/CakePHP controller conventions |
| **rust** | regex spec | actix-web (attributes, resources), axum routes, Rocket attributes, warp, tonic (`async_trait` impls), clap, lambda_runtime, cron; `impl` and `trait` owners, `mod`/`use crate::` resolution | macro-generated routes; trait-object dispatch beyond `impl` lookup |
| **swift** | regex spec | Vapor routes (`app.get("x", use: Handler(...).method)`), `extension` owners, SwiftUI/Foundation library calls | SwiftUI screens as entry points, Kitura |
| **c** | regex spec | main, civetweb `mg_set_request_handler`, libevent `evhttp_set_cb`, mongoose `mg_http_match_uri`, libmicrohttpd `strcmp(url, ...)`, nginx module handlers, signal handlers, getopt/argp CLIs; header includes resolved to files, `.field = fn` function-pointer tables and callbacks as `references`; libc and third-party headers become `libc`/library packages | no classes or objects (functions are the units, structs are class nodes); calls through function-pointer fields are not resolved to their targets; macros are not expanded (ALL-CAPS macro calls are not counted); the HTTP method of a registered handler is not known (`ANY`) |
| **cpp** | regex spec | classes, structs, templates, `Class::method` definitions in .cpp matched to the class in the header, `: public Base` inheritance and `override`, typed members (`T*`, `T&`, smart pointers, member declarations read from the same-stem header); entry points for Pistache, cpp-httplib (named handlers and lambdas), Crow, Drogon, oatpp and gRPC `X::Service` classes; `&Class::slot`/Qt `connect` callbacks as `references` | no overload resolution, no template instantiation or ADL; virtual dispatch through a base-class pointer resolves to the declared type's method (and an implementation if the base has none); macros are not expanded |
| **dart** | regex spec | classes, mixins, extensions, `package:` imports via `pubspec.yaml`, relative imports, `extends`/`implements`/`with`, typed fields and constructor `this._x` shorthand; Shelf/`shelf_router` routes and `@Route`, Dart Frog file routes, Serverpod endpoints, Flutter named routes and `GoRoute`, `MethodChannel` platform channels as shared nodes, `dart:io`/`dart:ffi` as library packages | no widget-tree analysis (screens are entry points, `build` bodies are scanned for calls only); Riverpod/get_it/Provider injection is not typed; a class that no import can be tied to is left unresolved rather than guessed |
| **perl** | regex spec | packages as classes, `sub` methods, `use`/`require` resolved to `.pm` files, `use parent`/`base`/`@ISA`/Mojo::Base inheritance, `$self->{field}->method` and `Class->new` typed receivers; Mojolicious (`->to('ctrl#action')`, Lite `get/post ... => sub`), Dancer2, Catalyst `:Path/:Local`, PSGI, CGI scripts; DBI/LWP/Storable/YAML sinks | calls without parentheses (`foo $x;`) and `AUTOLOAD`/string-based method names are not seen; heredocs are not masked; prototypes and `local` dispatch are not modelled |
| **abap** | regex spec | global and local classes (`DEFINITION`/`IMPLEMENTATION`, `INHERITING FROM`, `INTERFACES`, `REDEFINITION`), `FORM`/`PERFORM`, function modules and `CALL FUNCTION` (RFC destinations and SAP standard objects as library packages), `CALL METHOD`, `SUBMIT`, `NEW`/`CREATE OBJECT`, abapGit file layout, `.testclasses.abap`; entry points for REST `attach` routers, ICF `if_http_extension`, OData `*_create_entity`, function groups (RFC candidates), reports; `AUTHORITY-CHECK` as authentication evidence | the remote-enabled flag of a function module and SICF node paths live in metadata that is not parsed; statements are matched line by line (chained `:` statements and multi-line calls are partly seen); BAdI/enhancement implementations are not discovered |

Parsing is line-based and heuristic outside Python. Edges found that way carry confidence `medium` or `low`, and anything that cannot be resolved (dynamic dispatch, reflection, DI containers, macro-generated code) is listed in `system/coverage.md` with citations instead of being hidden. A source-to-sink link is always a candidate path, never proof.
